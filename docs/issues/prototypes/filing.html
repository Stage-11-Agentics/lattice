Filing an issue

Filing is settled and the same in every direction: one line of text, nothing else required, no story made and nothing planned. An agent files from the command line. A human files from the dashboard. Both land in the same log.

What an agent sees

Nothing is created on disk. The message speaks to the board owner, and the skill tells agents not to turn the feature on themselves: they leave a comment on the story they are working, or tell the human.

What a human sees

The dashboard

A + Issue button sits beside + New Task on every tab, and the i key opens the same panel. It works here.

or press i
Most recent issues

File one and it appears at the top. File and add another keeps the panel open, for writing down five things in a row after a walkthrough.

Where it goes

One log, two doors in, two ways to read

Who files

  • QA and research agentslattice issue file "..."
  • Build and review agents, in passingthe same command
  • A human at the dashboard+ Issue, or the i key
  • External usersnot in this build; their reports stay in the client app
→

The issue log

  • .lattice/issues/one event log per issue, beside the board, never mixed into it
  • Its own numbers: LAT-I42filing never uses up a story number
  • State is computed from the storiesopen, linked, resolved, dismissed, duplicate
  • Off by defaultone line in .lattice/config.json
→

Who reads and decides

  • A human, triagingmake a story, link, dismiss, mark duplicate
  • Any agent, readinglattice issue list, lattice show LAT-377
  • The boardnever shows issues in list, next or work-in-progress counts
  • A triage agentlater; by hand to start
An issue is an observation.It can be vague, wrong or a repeat. Filing one commits nobody to anything.
A story is a commitment.It is planned and reviewed. Several issues can become one story.
Nothing is deleted.Dismissed and duplicate issues keep their history and can be reopened.
